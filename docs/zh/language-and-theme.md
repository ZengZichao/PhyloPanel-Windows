# 语言与主题

两个开关都在顶栏右侧，都立即生效，不需要重启。

## 语言

**选项：** 中文 和 English。这两个名字固定用各自语言书写，这样无论当前是哪种语言，下拉框都
能读懂。

**切换覆盖的内容：**

- 顶栏所有控件、标签、提示和占位文字。
- 三列面板的标题，以及工作流、等价命令行、结果各区块。
- 参数表单全部文字：分组标题、`启用` 复选框、`(默认)` 选项、`默认 200` 标记、`浏览…`、
  位置参数标题及其说明。
- 状态提示、警告和错误——**包括 Rust 后端抛出的错误**。
- 空状态提示和图片的 alt 文本。
- 预设工作流的名称与说明、位置参数的帮助文本，这两类内容按工具整理在
  `src-tauri/toolpacks/*.json` 里。

**刻意不翻译的内容：** 命令 id 和参数说明。它们是从目标命令行自己的 `--help` 输出里实时读出来
的，属于 GoTree 或 GoAlign，而不属于 PhyloPanel。如果在面板里翻译它们，等于私自复制一份别人
的文档，并且每次上游发布都会悄悄过期。凡是面板自己写的文案，都是双语的。

**初始值怎么定：** 只要你没碰过这个控件，面板就读系统语言——`zh-*` 一律以中文启动，其余以英文
启动。一旦你手动选过，就以你的选择为准。

**存在哪里：** 应用本地存储的 `phylopanel.lang` 键，位于 `%LOCALAPPDATA%\app.phylo.panel\` 下的
WebView2 配置目录。跨重启、跨升级都保留。

**要加第三种语言** 只需三步：在 `src/i18n.ts` 里加一张文案表，扩展 `Lang` 联合类型，再给工具包
JSON 加上对应的字段。`src/i18n.ts` 里的 `missingKeys()` 会报告哪种语言缺哪个键。

## 主题

**选项：** 跟随系统、浅色、深色。

- **跟随系统** 通过 `prefers-color-scheme` 媒体查询解析，并持续跟踪：面板开着的时候改 Windows
  设置，界面会跟着变。
- **浅色** 和 **深色** 则固定住，不受系统设置影响。

选择还会通知窗口管理器，让 **Windows 原生标题栏**跟内容一致，而不是深色界面顶上一条白边。
在纯浏览器里（不带 Tauri 跑 `npm run dev`）这一步会被静默跳过。

**实现方式：** `src/styles.css` 里每一个颜色都是 CSS 自定义属性。浅色板子声明在 `:root`，
`[data-theme="dark"]` 块覆盖同一批属性名。没有任何一条规则硬编码颜色，所以加一套新配色只是改
token，不需要全文查找替换。解析出来的值写进 `<html data-theme>`，`color-scheme` 随之切换，
这才是让原生滚动条和表单控件一起变色的关键。

**对比度：** 两套配色都按 WCAG 文本对比度实测过，正文、次要文字、标题、分组行、按钮和命令行
区块在两种主题下都达到 4.5:1 以上。

**一个刻意的例外：** 图形框在深色主题下仍然是白底。GoTree 输出的 SVG 是黑字透明底、字号硬编码
8px，把框反过来就会让树看不见。也就是说*界面*变暗，*图*仍然落在纸上。

**持久化：** 本地存储的 `phylopanel.theme`，同一套配置目录。没有该键即"跟随系统"。

**已知限制：** 主题由脚本在文档解析完成后的一瞬间施加，因此当你显式选择的主题与系统设置相反时，
启动瞬间可能先以系统主题闪一下。**跟随系统**不会闪。

## 两者一起用

语言和主题互相独立，六种组合都可用，并且各自独立记忆。[README](../../README.zh-CN.md) 里的
截图就是英文/浅色与中文/深色两组。
