# 工作流与管道

## 管道模型

工作流就是一个有序命令列表。PhyloPanel 为每一步启动一个子进程，并用真实的操作系统管道把它们
接起来：第 *n* 步的 stdout 就是第 *n+1* 步的 stdin。中间结果不落盘，任何地方都不会产生临时
树文件。

```
输入 ──stdin──► [ 步骤 1 ] ──stdout──► [ 步骤 2 ] ──stdout──► [ 步骤 3 ] ──► 结果
```

有几个必须记住的推论：

- **顺序就是语义。** `reroot midpoint | draw svg` 画的是重根化后的树，反过来不是同一个操作。
- **会"吃掉"树的步骤只能当最后一步。** `stats`、`compare trees`、`matrix`、`labels` 打印的是
  报告而不是新的树，它们后面的步骤将拿不到输入。用到它们的预设都被标为 terminal。
- **所有步骤会一起启动，即使前面某步失败。** 进程是同时拉起的；第 1 步挂掉时，第 2 步只会收到
  空的 stdin 并通常也报错。结果区会分别显示每一步说了什么。
- **每步的退出码独立记录**，所以绿色行和红色行可以同时出现。

## 搭一条链

1. 在**命令表**里点命令，每点一个就追加到末尾。
2. 点某个步骤的标签来编辑它的参数。
3. 用 ↑ / ↓ 调序，× 删除。
4. **运行**。

**清空**只清工作流，保留输入路径或粘贴的文本，所以重建链条不必重新给树。

## 参数是怎么变成命令行的

面板刻意尽量少输出，这样生成的命令行既短，又和专家手敲的结果完全一致。

| 你的设置 | 实际产生 | 原因 |
|---|---|---|
| 布尔开关，关 | *什么都没有* | false 本来就是默认值。 |
| 布尔开关，开 | `--circular` | |
| 数字等于命令行默认值 | *什么都没有* | 重复默认值只是噪音。 |
| 数字不同于默认值 | `--height 400` | |
| 空的文本框 | *什么都没有* | |
| 列表框填 `a,b,c` | `--labels a,b,c` | `stringSlice` 类参数用逗号连接。 |
| 位置参数 `A B C` | `… prune A B C` | 追加在所有参数之后。 |

所以"表单全空"不等于"没应用任何选项"——它的意思是"按命令行工具自己的默认行为运行这个命令"。

## 输入的自动注入

选择**树文件**时，路径被自动加到第一步，必须同时满足：

1. 该步骤带有 `input` 角色的参数，并且
2. 你自己没有填那个参数。

如果你已经在该步骤自己的 `--input` 里写了值，以你写的为准。选择**直接粘贴**时根本不会加
`--input`，文本直接写进第一个进程的标准输入。

## 预设

预设来自工具包而不是硬编码在界面里，并且按工具区分。内置的 GoTree 工具包提供五个：

| 预设 | 链条 |
|---|---|
| 中点根化后绘图 | `reroot midpoint \| draw svg --width 900 --height 900` |
| 合并弱支持率分支后绘图 | `collapse support --support 0.7 \| draw svg --width 900 --height 900 --with-branch-support` |
| 辐射布局 | `draw svg --radial --width 900 --height 900` |
| 树统计 *（终止型）* | `stats` |
| Robinson-Foulds 比较 *（终止型）* | `compare trees --rf` |

点预设会替换当前工作流。如果某个预设引用了当前命令行版本里不存在的命令，面板会在状态栏告诉你
是哪个命令缺失，而不是塞给你一条半残的链。

## 位置参数

cobra 会在 `--help` 里描述参数，但不会描述裸参数，所以这部分无法反射，只能由工具包人工标注。
GoTree 有四个命令需要它：

| 命令 | 需要什么 |
|---|---|
| `reroot outgroup` | 定义外群的分类单元名（或改用 `--tip-file`） |
| `collapse clade` | 定义要合并的支系的分类单元名 |
| `prune` | 要移除的分类单元名 |
| `upload itol` | 要上传到 iTOL 的树文件 |

选中这些命令时，表单会出现**位置参数**输入框，值之间用空格分隔。顺带一提，GoTree 自己的命名
就不统一：`reroot outgroup` 用 `--tip-file`，而 `prune` 用 `--tipfile`——这正是面板必须按
*语义角色*而不是参数名来组织表单的原因。

## 配方

**从文件出发，画一张能投稿的辐射 SVG**

```
unroot | reroot midpoint | collapse support --support 0.95 | draw svg --radial --width 1200 --height 1200
```

**比较两棵树的拓扑并把数字留下**

```
compare trees --rf --input reference.tre
```

**从贝叶斯树集里抽样再汇总**

```
sample --number 100 | stats
```

**按映射文件改名后输出文本树**

```
rename --node-file map.txt | draw text --width 60
```

终端里能做的事，这里都能做；等价命令行就是校验手段——它看着不对，跑出来就一定不对。
